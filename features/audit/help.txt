meowsky audit [<directory>] [--quick] [--refresh]
meowsky audit [<directory>] --refactor-prompt <ID[,ID...]>
Validate a local workspace directory. Defaults to the current directory.
The directory may be relative to the current location or an absolute path.
Git is optional; discovery reads the filesystem directly.
Options may appear before or after the directory.

--quick    Show filesystem discovery and concise static findings without Codex.
--refresh  Write .meowsky/AUDIT.md and a compact .meowsky/MAP.md from the
           current audit. Existing changed files are backed up before
           replacement. With --quick, both outputs label absent Codex context.
--refactor-prompt  Print a planning prompt for 1-12 comma-separated finding
           IDs from the saved AUDIT.md; requires the saved MAP.md too. This
           option reads files only, invokes no Codex session, and cannot be
           combined with --quick or --refresh. Quote comma-separated IDs in
           PowerShell so they remain one argument.
--help     Show this help when used alone. -h and -Help also show feature help.

Discovery lists relevant source, test, configuration, and documentation files.
It excludes common dependencies, generated output, caches, temporary files, and
.meowsky/. Optional .meowskyignore lines name exact project-relative files or
directories (including their contents); blank lines and # comments are ignored.
Unfamiliar file types, project exclusions, and broad names such as dist/ or
vendor/ are reported as coverage limits because they may hide relevant source.
Wildcards and parent paths are not supported. Scan limits are 20,000 entries,
30 directory levels, and 30 seconds. Skipped paths and incomplete coverage are
reported; the command does not follow junctions or symlinks.

Static checks verify local Markdown links and image targets, and suggest review
for source files over 500 lines or 64 KiB, or directories with over 40 direct
source/test files. These thresholds can be changed when calling the checks
function directly. A script or test without a Markdown link is flagged only
when a peer in the same directory has a documented link. These are review
candidates, not claims of dead code. Skipped or unreadable paths are reported
as coverage limitations. Findings stay in memory and have stable report IDs.
Markdown files over 1 MiB and complex link syntax are reported as coverage
limits instead of being called broken links. Links outside the audited root
and section anchors are not verified.

Without --quick, Audit also runs a bounded Codex semantic review. It may incur
Codex usage. The review samples relevant files and evaluates maintainability,
architecture, naming, obsolete or redundant logic, and documentation. Findings
must cite inspected source paths and recommend proportionate action. A clean
review may have no findings. Failed or incomplete reviews are labeled clearly.

Codex runs non-interactively with a read-only sandbox, no approval escalation,
disabled hooks/plugins/apps, no user config, an ephemeral session, and a
180-second timeout. The prompt forbids project tooling, tests, and edits; the
sandbox enforces the target file-write boundary. The bounded summary and
structured response stay in memory unless --refresh writes the Markdown report.
Normal audits do not write project files. Report source links are checked
against the discovery inventory at generation time; semantic claims still need
human verification. The map links to inventoried source, tests, and docs and
labels static candidates separately from bounded Codex interpretations. It
is a snapshot from the last explicit --refresh; there are no update hooks.
Valid report links establish that paths existed at generation time; they do
not prove a semantic claim. The bounded review does not inspect every file.
Codex failures or incomplete coverage are disclosed, not treated as success.
Audit does not edit application source files.

Refactoring workflow: run meowsky audit <directory> --refresh, review the two
generated files, then select IDs shown in AUDIT.md. Run
meowsky audit <directory> --refactor-prompt 'V001,S002' and copy its output into
an interactive meowsky codex <directory> session. In PowerShell, append
| Set-Clipboard to the prompt command to copy it. Codex must verify the current
source and present a scoped plan, then wait for explicit edit approval. The
same template is in features/audit/refactor-prompt.md for manual use: replace
its placeholders, verify the selected IDs, and follow its checklist yourself.
