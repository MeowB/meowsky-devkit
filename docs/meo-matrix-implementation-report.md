# Meo Matrix implementation report

This report describes the **current repository implementation, including staged changes**, inspected on 2026-09-27. No files or system settings were changed during the inspection.

The inventory covers colors **owned or generated by Identity**. Windows rendering, the selected VS Code base theme, language providers, preserved settings, and profile overrides can contribute additional colors that Identity does not define.

## 1. Identity source of truth

The complete current [`meo-matrix.json`](../features/identity/themes/meo-matrix.json) is:

```json

  "id": "meo-matrix",
  "name": "Meo Matrix",
  "ui": {
    "background": "#050806",
    "surface": "#0B110D",
    "surfaceRaised": "#102516",
    "text": "#C7F9CC",
    "terminalText": "#39FF14",
    "terminalBackground": "#000000",
    "terminalBlack": "#182019",

    "accent": "#39FF14",
    "accentBright": "#4AFF64",
    "accentSoft": "#8FFFA0",
    "selection": "#204D27",
    "warning": "#FFD866",
    "error": "#FF5C57"
  },
  "syntax": {
    "text": "#C7F9CC",
    "comment": "#52705A",
    "keyword": "#39FF14",
    "function": "#8FFFA0",
    "type": "#65D97A",
    "string": "#B8D96C",
    "number": "#D7FF87",
    "constant": "#72E5C2",
    "operator": "#91AA96",
    "error": "#FF5C57",
    "warning": "#FFD866"
  },
  "windows": {
    "mode": "normal",
    "systemTheme": "dark",
    "appTheme": "dark",
    "accent": "ui.accent",
    "transparency": true
  },
  "preferences": {
    "cursor": {
      "style": "block"
    }
  }
}
```

The JSON contains **25 color roles with 19 distinct RGB values**. Those values, metadata, and preferences are the source of truth.

Adapters derive:

- Windows accent shades and registry color encodings.
- Terminal blue and purple through hue rotation.
- Six Terminal bright colors through white blending.
- Four VS Code colors through appended alpha values.
- Application-specific cursor names.
- The mapping of semantic roles to application properties.

The Windows accent references `ui.accent`; it does not duplicate its hex value. Other equal colors—such as `ui.text` and `syntax.text`—are independently defined roles, not references.

The optional terminal roles separate terminal backgrounds (`ui.terminalBackground`, `#000000`) and ANSI black (`ui.terminalBlack`, `#182019`) from the general Windows/editor background. Older themes fall back to `ui.background` for Windows Terminal background and ANSI black, and for VS Code terminal/cursor backgrounds. VS Code leaves ANSI black untouched if its dedicated role is absent.

`docs/Identity-meo-matrix.png` is a design reference. No implementation extracts colors from it.

## 3. Windows normal mode

Normal mode is the configured default. Its implementation is in [`windows-normal.ps1`](../features/identity/adapters/windows-normal.ps1) and [`windows-native.ps1`](../features/identity/adapters/windows-native.ps1).

It applies dark system mode, dark app mode, `#39FF14` accent, and enabled transparency.

These are the **eight directly managed registry values**, all under `HKEY_CURRENT_USER`:

| Registry key | Value | Type | Final value |
|---|---|---|---|
| `Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` | `SystemUsesLightTheme` | DWORD | `0` |
| Same | `AppsUseLightTheme` | DWORD | `0` |
| Same | `EnableTransparency` | DWORD | `1` |
| `Control Panel\Desktop` | `AutoColorization` | DWORD | `0` |
| `Software\Microsoft\Windows\DWM` | `AccentColor` | DWORD | `0xFF14FF39`, ABGR encoding |
| Same | `ColorizationColor` | DWORD | `0xFF39FF14`, ARGB encoding |
| `Software\Microsoft\Windows\CurrentVersion\Explorer\Accent` | `AccentColorMenu` | DWORD | `0xFF14FF39`, ABGR encoding |
| Same | `AccentPalette` | Binary | Seven derived accent slots; eighth slot preserved |

The palette’s first seven slots are:

```text
#BAFFAD #88FF72 #61FF43 #39FF14 #2ECC10 #22990C #145907
```

Each generated slot occupies four bytes: RGB followed by a reserved zero byte. That zero is **not an opacity setting**.

Expected visual effects are dark rendering in Windows shell areas and applications that honor the corresponding preferences, identity accent rendering in controls that consume Windows accent colors, and transparency where Windows supports it. These are intended effects of the settings, not verified pixel-level guarantees.

Important boundaries:

- Start/taskbar and title-bar/border accent visibility switches are preserved.
- Normal mode does not force their accent visibility on.
- It cannot assign `ui.background` to Explorer globally.
- It does not assign arbitrary global text, button, selection, or border colors.
- It does not control application-owned themes or borders.
- It does not change wallpaper or the global pointer/caret style.

Before changes, it writes a scoped `.reg` backup under:

```text
%LOCALAPPDATA%\Meowsky\Identity\Backups
```

Matching reapplication performs no registry write, backup, or refresh. Unexpected existing value types or a non-32-byte existing accent palette are rejected.

If contrast is active, normal application attempts `SPI_SETHIGHCONTRAST` to clear `HCF_HIGHCONTRASTON`, preserving accessibility settings and the scheme. Windows performs the normal-rendering restoration; the adapter then reapplies its normal preferences. Failure produces a manual instruction:

```text
Settings > Accessibility > Contrast themes > None > Apply
```

Changed application broadcasts `WM_SETTINGCHANGE` with `ImmersiveColorSet`. Applications that ignore or cache the notification may need reopening. No Explorer restart, logout, or reboot is forced.

Registry writes are individually verified, not atomic as a group. Partial failures retain the backup and are reported.

```text
round(channel + (255 - channel) × 0.25)
```

The adapter also sets:

```json
{
  "profiles.defaults.colorScheme": "Meo Matrix",
  "profiles.defaults.cursorShape": "filledBox"
}
```

`filledBox` is the Windows Terminal translation of the identity’s `block` preference.

Identity does not change Terminal fonts, opacity, acrylic settings, layouts, startup behavior, cursor height, animations, or individual profile overrides. Existing profiles can override the defaults. Existing Matrix animation/header behavior remains outside this palette mapping.

## 8. Language coverage

All languages can consume the same global semantic rules **if a provider emits matching tokens**. Identity does not install or run those providers.

The repository’s tokenizer harness contains **68 foreground probes across 14 language samples**. It checks TextMate behavior, not semantic language services or rendered pixels. C++ is not a separate harness case.

| Language | Semantic-token coverage | TextMate/sample coverage | Specific mappings or known gaps |
|---|---|---|---|
| C | Global selectors cover recognized types, functions, variables, fields, macros and readonly symbols; provider-dependent | 16 probes: directives, macros, modifiers, built-in types, functions, identifiers, literals, operators, comments | User-defined `Item` remains text in the tested grammar; semantic classification is needed for type coloring |
| C++ | Same global selectors, including classes, namespaces and methods; provider-dependent | No dedicated C++ sample or tokenizer case | C++-specific behavior is not verified by this repository harness |
| JavaScript | Global selectors; actual provider emissions not tested | 5 probes: comments, functions, keywords, strings, numbers | No JavaScript-qualified rules; readonly coloring depends on classification |
| TypeScript | Global selectors include interfaces/type parameters/types/methods | 4 probes: interface name, function, number, string | No TypeScript-qualified rules; semantic emissions not tested |
| Python | Global selectors; provider-dependent | 5 probes: comments, function, keyword, string, number | Rich symbol/type distinctions require appropriate provider classifications |
| HTML | Global selectors where supplied | 4 probes: comments, tags, attribute values, embedded JavaScript | Explicit tag/attribute fallback scopes; embedded code follows its grammar |
| CSS | Global selectors where supplied | 4 probes: comments, selector, string, number | Explicit class/ID scopes; properties are text; observed `px` unit scope uses keyword green |
| SCSS | Global selectors where supplied | 3 probes: comments, number, string | Explicit SCSS class/ID scopes; variables have text fallback; no dedicated mixin semantic rule |
| PowerShell | Global selectors; provider-dependent | 4 probes: comments, function, keyword, string | No PowerShell-qualified rules; variable/cmdlet distinctions follow emitted scopes |
| Bash | Global selectors if a provider supplies them | 4 probes: comments, function, keyword, string | No Bash-qualified rules; ordinary variables share text |
| JSON | Global selectors where supplied | 3 probes: number, string, boolean | Keys fall under text; lexical booleans use constant |
| YAML | Global selectors where supplied | 4 probes: comments, number, string, boolean | Observed keys use type color; no dedicated YAML-key rule |
| Dockerfile | Global selectors where supplied | 3 probes: comments, instruction keyword, string | No dedicated Dockerfile rules beyond generic scopes |
| SQL | Global selectors where supplied | 5 probes: comments, keyword, number, string, NULL | Tested grammar classifies `NULL` as keyword: `#39FF14`, unlike C |
| Markdown | Global selectors where supplied | 4 probes: heading, inline code, embedded C type/function | No dedicated link URL, emphasis, quotation, or list-marker color rules |

For this inspection, additional **read-only in-memory tokenizer probes** confirmed YAML keys, JSON keys, Markdown links/emphasis, HTML punctuation, CSS properties/units, and SCSS variables. They used the installed grammar with the generated Identity rules and default editor foreground. They did not load the user’s complete base-theme styling or semantic providers.

## 10. Duplication and inconsistencies

These are observations only; nothing was changed.

| Finding | Actual implemented state |
|---|---|
| Duplicate source colors | `ui.terminalText`, `ui.accent`, `syntax.keyword` match; `ui.text`/`syntax.text`, `ui.accentSoft`/`syntax.function`, and UI/syntax error/warning pairs also match |
| Equal colors are independent definitions | Except the Windows accent reference, equal-role values can diverge through future JSON edits |
| Integrated-terminal ANSI mismatch | Both terminals use `#182019` for ANSI black; Windows Terminal gets the complete Matrix ANSI palette, while other VS Code integrated ANSI colors remain inherited |
| Identifier categories collapse | Variables, parameters, properties, events and labels share text; readonly variants share constant |
| Type categories collapse | Types, classes, structs, enums, interfaces, type parameters and namespaces share one color |
| JSON/YAML key difference | JSON keys use text; observed YAML keys use type |
| NULL differs by language | C lexical NULL uses constant/cyan; tested SQL NULL uses keyword/green |
| Comments and inactive text differ | Comments use `#52705A`; muted UI/ANSI bright black use `#66806A` |
| Active/inactive selections match | Editor active/inactive selection backgrounds match; list active/inactive selection backgrounds and foregrounds match |
| Active window border is darker | Active border `#204D27` is darker than inactive `#66806A`; both VS Code and contrast mappings use this relationship |
| Focus and window borders differ | Control focus uses bright `#39FF14`; active outer window border uses dark `#204D27` |
| Secondary button hover is unchanged | Secondary normal and hover backgrounds both use `#102516` |
| Debugging reuses warning | Debugging status background is yellow without necessarily indicating a warning |
| ANSI black remains subdued | ANSI black `#182019` is separate from terminal background `#000000`, but remains deliberately dark |
| Bright-color construction is asymmetric | Bright black/green are direct semantic roles; six other bright entries use a 25% white blend |
| Presentation values live in adapters | Hue offsets, Windows shade blends, Terminal bright blend and VS Code alpha values are not configurable theme fields |
| Some Markdown constructs are unowned | Link URLs, emphasis, quotations and list-specific styling can remain base-theme-dependent |
| Broad fallback scopes affect embedded syntax | `source`, `variable`, `punctuation` and `keyword` rules apply widely; the emitted scope hierarchy determines refinements |
| Normal Windows does not reproduce the full palette | It applies theme mode/accent/transparency, not arbitrary Matrix window/text/control RGB |
| Contrast has no dedicated error/warning mapping | Its system-color mapping does not consume those UI roles or any syntax role |
| Font appearance is not fixed by Identity | Existing/base-theme font styles are preserved |
| Physical rendering is not fully fixed | Scoped settings, providers, individual Terminal profiles, Windows accessibility behavior and unowned theme properties can affect the result |

**All 25 defined color roles are consumed somewhere in the implementation.** No globally unused theme color was found. Some roles are naturally unused by individual adapters.
